# Security policy

Do not report secrets, access tokens, personal data, or private database exports in public issues. Do not place credentials in source files, JSON research records, logs, or the desktop executable.

Until a dedicated secure publishing service exists, submit proposed records as pull requests. Maintainers should review source provenance, record continuity, and the checkpoint proposal before merging.

For a suspected security issue, contact the repository maintainer privately through GitHub's private vulnerability reporting feature if enabled. Do not include exploit details in public issues.
